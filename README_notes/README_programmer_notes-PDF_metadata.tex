This document describes how metadata can be added to a \gls{PDF} file. \Cref{sec:addingKeywordsAndMetaDataToPDF} describes some background and my earlier implementation, while \Cref{sec:modernMetadataApproach} describes a modern approach to metadata.

\section{Adding keywords and other data to PDF metadata}
\label{sec:addingKeywordsAndMetaDataToPDF}
The \texttt{hyperref} package is used to add \gls{PDF} metadata. However, to add the English and Swedish keywords as part of the \gls{PDF} metadata, you must know the keywords \textit{before} the \textbackslash begin\{document\} command in the \LaTeX{}~file. To do so, I added three new commands to the \texttt{kththesis.cls} file, as shown in \Cref{lst:keywords}. The commands are used in the \fname{examplethesis.tex} file to set up the keywords in both English and Swedish. Additionally, a new set of \LaTeX{} commands are used to store the \gls{PDF} metadata (as shown in \Cref{lst:storingkeywords}) using a file called \fname{lib/pdf\_related\_includes.tex} (shown in \Cref{lst:informationforPDFfile}). Later, the stored keywords are inserted into the \LaTeX{}~after their respective language abstracts. The title page of the thesis and the PDF metadata are shown in \Cref{fig:pdfMetadata}. Note that both the English and Swedish versions of the keywords are included in the metadata. Finally, the keywords appear (as expected) in the \enquote{For DiVA} data at the end of the \gls{PDF} file.

\Needspace*{7\baselineskip}
Note that \texttt{\textbackslash makeatletter} and \texttt{\textbackslash makeatother} are used to include the character “@” as a letter and then return “@” to being a punctuation code. This use of “@” protects the internal names from being accessed outside of these two commands. More explicitly, \texttt{\textbackslash EnglishKeywords} is a function that takes one argument, the text of the English keywords, and then stores them into \enquote{\texttt{@EnglishKeywords}}. Later, the text can be retrieved with the command \texttt{\textbackslash InsertKeywords\{english\}} or \texttt{\textbackslash InsertKeywords\{swedish\}}.
\Needspace*{15\baselineskip}
\begin{lstlisting}[language={[LaTeX]TeX}, caption={New commands in kththesis.cls}, label=lst:keywords]
% Keywords
\let\@EnglishKeywords\@empty
\newcommand{\EnglishKeywords}[1]{\def\@EnglishKeywords{#1}}

\let\@SwedishKeywords\@empty
\newcommand{\SwedishKeywords}[1]{\def\@SwedishKeywords{#1}}

\newcommand{\InsertKeywords}[1]{
    \IfEqCase{#1}{%
    {english}{\@EnglishKeywords}

\end{lstlisting}

\end{lstlisting}


The \fname{lib/pdf\_related\_includes.tex} file contains the \LaTeX{} ~-- to add information
to the \gls{PDF} file (specifically, author(s), title(s), and keywords). It uses the
\texttt{hyperref} package and should be included before the \texttt{\textbackslash begin\{document\}}.
I want to acknowledge the inspiration from Karl Voit's template for TU Graz, which inspired me to add the \gls{PDF} document information. For more information about his template, see \url{https://github.com/novoid/LaTeX-KOMA-template}
Note that my template does not use anything from his template other than the names of the information for the \gls{PDF} meta fields, \ie \texttt{mytitle}, \texttt{myauthor}, and \texttt{mykeywords}, together with the idea of defining the corresponding \texttt{newcommand} to set the relevant \texttt{hyperref} parameters. As a result, these command names are visible to the rest of the \LaTeX{} file. See \Cref{lst:informationforPDFfile} for the code.

In keeping with the Swedish standard (\foreignlanguage{swedish}{Svenska skrivregler [Språkrådet 1.6.3 och 12.11.5]}) a \enquote{\foreignlanguage{swedish}{mellanslag tankstreck}} with a space before and after, \ie \enquote{\hbox{ – }} is used to separate the title and subtitle when in Swedish, this leads to a condition based on whether the document is in Swedish or not in the computation of \texttt{mytitle} and \texttt{myalttitle}.

Initially, the template used the \texttt{hyperxmp} package to add support for the \gls{PDF} metadata for the copyright notice. Because of this, if the author's name includes a suffix such as \enquote{, Jr.} or \enquote{ Jr.}, \ie the suffix can be separated with a comma or not as the author prefers to write their name; thus, there was a need to change the processing of \texttt{pdfauthor} information, as \texttt{hyperxmp} treats comma-separated strings in the author or keywords fields as being a list and converts these into a sequence of data in the metadata. This change is shown in \Cref{lst:informationforPDFfile} where the \texttt{\textbackslash hyxmp@comma} macro is used to insert something that is later replaced by a comma but is not treated as a comma when processing the \texttt{pdfauthor} information. The command \texttt{\textbackslash xmpquote} is used to wrap the whole name.

\noindent \textbf{NB} The \texttt{hyperxmp} package is no longer used, as \texttt{\textbackslash DocumentMetadata} and \texttt{hyperref} now natively support \gls{PDF} metadata.

\subsection{Adding additional metadata to the PDF file}
\label{sec:addingMetadataToPDFfile}
Increasingly, metadata is being embedded into digital objects to provide information about the creator (author, photographer, \etc), date of creation, copyright notices, \etc. In a typical \gls{PDF} file produced by \LaTeX{}, there is both PDF-specific metadata and additional metadata. This additional metadata is stored using Adobe's \glsfirst{XMP}. \gls{XMP} is a means of embedding metadata in \gls{XMP} format into \gls{PDF} documents so that tools can extract it mechanically.

An early paper about automatically extracting the title, author(s), and abstract from theses was written by Mao Ni of the University of North Carolina at Chapel Hill, School of Library and Information Science in 2004~\cite{Mao_Ni_2004}. The idea was to collect the metadata from the thesis using an Adobe Acrobat plugin and then write this data to \gls{XMP} (which could be embedded into the \gls{PDF} file). The schema used for the metadata~\cite{hickey_pavani_suleman_2010} \footnote{\url{https://ndltd.org/metadata/}} was that of Networked Digital Library of Theses and Dissertations\footnote{\url{https://ndltd.org/}}.

More recently, Elsevier's Digital Commons \footnote{\url{https://www.elsevier.com/solutions/digital-commons}} uses an extension of the Dublin Core\footnote{\url{https://www.dublincore.org/}} shown in \Cref{tab:dublinCoreDigitalCommons} to collect metadata. We will see the Dublin Core elements and other metadata schema used in \gls{XMP} in the remainder of this section.

Bepress has written about Elsevier's Digital Commons on a webpage \enquote{Digital Commons and OAI-PMH: Outbound Harvesting of Repository Records} \url{https://bepress.com/reference_guide_dc/digital-commons-oai-harvesting/}. \gls{OAI-PMH} fosters interoperability between repositories\footnote{\url{https://www.openarchives.org/pmh/}} by enabling harvesters to collect metadata from a repository. Over the last 20 years, there has been an evolution from simply having metadata in a database that is associated with a publication to an entire ecosystem of metadata and applications; see, for example, the twentieth International Conference on Dublin Core and Metadata Applications (DCMI 2022) \url{https://www.dublincore.org/conferences/2022/programme/}.

The \gls{XMP} data is in a stream indicated in the \gls{PDF} as Metadata of the subtype \gls{XML}, as shown in \Cref{lst:pdfXMPStream}. In the listing, the actual length in bytes has been replaced by dddd.
\begin{lstlisting}[caption={PDF stream where the XMP is found}, label=lst:pdfXMPStream]
<< /Subtype /XML /Type /Metadata /Length dddd >>
stream
\end{lstlisting}

In the \gls{PDF} file, the \gls{XML} encoded metadata is between \texttt{<?xpacket begin="yyyy" id="xxxx"?>} and \texttt{<?xpacket end="w"?>} (where xxxx is some unique ID). While this character is a valid \mbox{UTF-8} character, the \texttt{lstlisting} environment cannot handle this value; therefore, it has been replaced by the string \enquote{BOM 0xFEFF}. \subsection{Extending the set of elements for theses}
\label{sec:newMetadataForTheses}
Even with the various schemas included in \gls{XMP}, DiVA still needs metadata that cannot yet be easily included and embedded in \gls{XMP}. Thus, the extra metadata needs to be collected and processed via some mechanism other than \gls{XMP}.

For \gls{XMP}, there are some specific areas that might be of interest in the future:
\begin{itemize}
  \item Adding new dc elements (§\,\ref{sec:newDCelements}) 
  \item Adding references to the metadata (§\,\ref{sec:addingReferences}), and 
  \item Adding citation data to the metadata (§\,\ref{sec:addingCitation})
\end{itemize}

\subsubsection{Adding new dc elements}
\label{sec:newDCelements}
In \Cref{tab:dublinCoreDigitalCommons} on \pageref{tab:dublinCoreDigitalCommons} we saw five elements that are perhaps worth adding, specifically:
\texttt{thesis.degree}, \texttt{thesis.degree.discipline}, \linebreak[4]\texttt{thesis.degree.grantor}, \texttt{thesis.degree.level}, and \linebreak[4] \texttt{thesis.degree.name}. It may be worth adding these to the XMP data for a thesis in the future. For some discussion of these elements, please see the discussion of EDT‐MS metadata elements in the paper by Ivanović, Ivanović, and Surla entitled \textit{A data model of theses and dissertations compatible with {CERIF}, {Dublin} {Core} and {EDT}‐{MS}}~\cite{ivanovic_data_2012}. ETD-MS is defined in \textit{ETD-MS v1.1: an Interoperability Metadata Standard for Electronic Theses and Dissertations}~\cite{hickey_pavani_suleman_2010} and available at \url{https://ndltd.org/wp-content/uploads/2021/04/etd-ms-v1.1.html}.


\subsubsection{Adding references to the metadata}
\label{sec:addingReferences}
Increasingly, there is interest in easily knowing which references a thesis cites. Part of this interest is to be able to compute citation maps (who cites whom) and to examine the types of sources that are cited.

There are several possibilities for storing information about references. One is the element \texttt{dc.relation.references}. Another possibility is to use the \texttt{dcterms:references} element refinement of \texttt{dc:relation} as proposed in 1998 by Ann Apps of the Dublin Core Metadata Initiative (DCMI) Citations Working Group (\url{https://www.dublincore.org/groups/citation/}).

\Needspace*{9\baselineskip}
More recently, a new schema was proposed by CrossRef; see \url{https://www.crossref.org/documentation/schema-library/markup-guide-metadata-segments/references/}. Note that the focus of this work is to facilitate depositing with CrossRef the list of references used in a publication. Their set of elements is shown in \Cref{tab:crossRefElementsForCitationTagging}\footnote{\url{https://www.crossref.org/documentation/schema-library/markup-guide-metadata-segments/references/\#00178}}. Note that while the focus seems to be on journal articles, they also have a \enquote{Metadata best practices} website with lots of examples of metadata for different types of documents; see \url{https://www.crossref.org/documentation/principles-practices/best-practices/}.

\subsubsection{Adding citation data to the metadata}
\label{sec:addingCitation}
There is also a desire by many to include bibliographic citation information into the \gls{XMP} so that the \gls{PDF} carries this data and one does \emph{not} need to access some other source to find this information. The element \texttt{DCTERMS.bibliographicCitation} is proposed for this purpose in a document by Ann Apps, \textit{Guidelines for Encoding Bibliographic Citation Information in Dublin Core™ Metadata}~\cite{Ann_Apps_2005}.

\Needspace*{3\baselineskip}

At present, I think the easiest method to provide citation data is to embed a file containing the \BibLaTeX{} entries used. Note that the GitHub workflow and script \fname{bib\_cleanup.py} process the \fname{references.bib} file and produce a \fname{referencesUsed.bib} file that could be embedded in the \gls{PDF}. An advantage of this approach is that you can extract this file and get the bibliographic entries used --- in machine-readable form that can be used directly with \LaTeX. Further details are given in \Cref{sec:metadataVersusEmbeddedFiles}.

\label{sec:modernMetadataApproach}

This section describes a modern approach via \textbackslash DocumentMetadata and Tagged \gls{PDF} standards to provide metadata and to help ensure both indexability and accessibility of documents into the future. \Cref{sec:ModernMetadataApproach} introduces the modern \LaTeX{} kernel approach via \textbackslash DocumentMetadata).

\subsection{The Modern LaTeX Kernel Approach (\textbackslash DocumentMetadata)}
\label{sec:ModernMetadataApproach}
The \LaTeX{} Project introduced \texttt{\textbackslash DocumentMetadata\{\dots\}} to be executed \textbf{before} \texttt{\textbackslash documentclass}. Its primary role is to initialize the PDF management layer, enforce compliance standards (such as PDF/A-2u or  PDF/A-3u), and configure global output intents before any packages or fonts are loaded: \Cref{lst:exampleDocumentMetadata} and \Cref{lst:anotherExampleDocumentMetadata} show examples of using this new command. This key-value approach differs from the old \texttt{hyperref} / \texttt{hyperxmp} preamble injection model. However, you must know all this information before the \texttt{\textbackslash documentclass}.

\Needspace*{10\baselineskip}
\begin{lstlisting}[language={[LaTeX]TeX}, caption={Example of using \texttt{\textbackslash DocumentMetadata}}, label=lst:exampleDocumentMetadata]
\DocumentMetadata{
    % pdfversion  = 2.0,
    % pdfstandard = A-4,
    pdfversion=1.7,
    pdfstandard=a-3u,
    lang        = en-US
}
\end{lstlisting}

\Needspace*{14\baselineskip}
\begin{lstlisting}[language={[LaTeX]TeX}, caption={Second example of using \texttt{\textbackslash DocumentMetadata}}, label=lst:anotherExampleDocumentMetadata]
\DocumentMetadata{
  lang        = en-US,
  pdfversion  = 1.7,
  pdfstandard = a-2u,
}
\end{lstlisting}

It is important to note that \texttt{\textbackslash DocumentMetadata} does not accept content-level document properties (such as \texttt{author}, \texttt{title}, or \texttt{keywords}). Instead, content-level properties are declared in the preamble using \texttt{\textbackslash hypersetup\{\dots\}} or injected directly into the kernel's \gls{XMP} data stream via \texttt{\textbackslash pdfmeta\_xmp\_add:n}. When the \texttt{hyperref} package loads, it automatically connects to the active \gls{PDF} management layer and populates the conforming \gls{PDF} catalog and \gls{XMP} packet.

The actual \fname{examplethesis.tex} file only uses the top level values shown in \Cref{lst:exampleDocumentMetadata} and then later makes use of the code in \fname{lib/pdf\_related\_includes.tex} to assemble \texttt{pdftitle}, \texttt{pdfauthor}, \texttt{pdfkeywords}, and \texttt{pdfsubject} using \texttt{expl3} routines (\texttt{\textbackslash build\_tagged\_keywords:}, \texttt{\textbackslash build\_pdf\_subject:}, \texttt{\textbackslash inject\_prism\_metadata:}, and \texttt{\textbackslash inject\_publisher\_metadata}).

While there might seem to be a design conflict with the dynamic, multilingual thesis workflow of the thesis, since \texttt{\textbackslash DocumentMetadata} evaluates before \fname{custom\_configuration.tex} or the toggle \texttt{\textbackslash ifinswedish} is known. Fortunately, the initial \texttt{lang = en-US} setting is mutable. Once the language configuration is determined, the document's primary language can be updated in \fname{lib/pdf\_related\_includes.tex} by issuing \texttt{\textbackslash hypersetup\{pdflang=\{sv-SE\}\}} (or through the kernel interface \texttt{\textbackslash pdfmeta\_lang\_set:n \{ sv-SE \}}), which rebinds the \texttt{/Lang} entry in the \gls{PDF} Catalog and ensures correct language tagging in the output stream.

\subsection{PDF/A, PDF/UA, and Long-Term Archival at KTH}
\label{sec:longTermArchiving}
\gls{DiVA}'s mission is twofold: open-access dissemination and compliance with national long-term archiving mandates. Because, in its second role, \gls{DiVA} feeds the Swedish National Archives (\foreignlanguage{swedish}{Riksarkivet}) and the National Library of Sweden (\foreignlanguage{swedish}{Kungliga biblioteket}), it directly inherits the national preservation directives.

Riksarkivet's official regulatory framework (RA-FS) explicitly establishes PDF/A-1 as the baseline mandated standard for long-term document preservation. For example, conformance level (b), \ie Level B (Basic), ensures exact \textit{visual replication} over centuries. The goal is that a third-cycle thesis uploaded today will look exactly the same when opened in 100 years, regardless of operating system or device. Unfortunately, PDF/A-1b does \textbf{not} mandate Unicode text mapping. Under Swedish National Archives (\foreignlanguage{swedish}{Riksarkivet}) regulations, academic publications intended for permanent deposit should preserve:
\begin{itemize}
    \item \textbf{Color Profiles:} Device-independent color representations via embedded ICC profiles.
    \item \textbf{Font Embedding and Unicode Mapping:} Complete embedding of all font subsets, along with valid \texttt{ToUnicode} mappings to guarantee text extractability.
    \item \textbf{Standardized XMP Stream Structure:} Validation of embedded \gls{XMP} streams without proprietary syntax extensions or unescaped delimiter conflicts.
\end{itemize}


Fischer, Lundell, and Gamalielsson examined the use of fonts and file formats for long-term maintenance of digital assets by (three types of) Swedish public sector organizations~\cite{fischer_pdfconformance_2023}. For universities, they selected \num{9341} unique doctoral dissertations with \gls{PDF} files from 28 universities. They selected \num{5931} \glspl{PDF} from the Swedish Code of
Statutes (\foreignlanguage{swedish}{Svensk författningssamling} (SFS)). Finally, they selected \num{155} additional \gls{PDF} files from Swedish Government Official Reports (\foreignlanguage{swedish}{Statens offentliga utredningar} (SOU) submissions). They found that many \gls{PDF} files not only failed to meet PDF/A-1 requirements for font availability, but also used fonts they did not necessarily have a license to embed, and many did not embed the fonts they used. As a result, each user must find the fonts to render the document, reducing its long-term accessibility.

\Needspace*{14\baselineskip}
Increasingly, the university libraries administering \gls{DiVA} favor PDF/A-2u. Conformance level, \ie Level U (Unicode), guarantees everything Level B does regarding visual fidelity, but adds a strict prerequisite: all text must map cleanly to Unicode semantics. This has two advantages:
\begin{enumerate}
    \item Search Engine Visibility: PDF/A-2u is structurally guaranteed to be cleanly indexable by web crawlers, supporting DiVA's core mandate for open-access visibility; and
    
    \item Visual Transparency: PDF/A-2 allows transparency, layers, and modern OpenType fonts, which are common in thesis covers, complex charts, and scientific figures. PDF/A2u addresses unicode mapping (with ToUnicode CMaps), embedded ICC color profiles, and the elimination of non-standard font encoding anomalies. [\textbf{NB} Current information from USAB is that transparency is \textbf{not} allowed in a thesis they print and that the \gls{PDF} file that they produce is \textbf{not} designed to be accessible (\ie it has been optimized for printing).]
\end{enumerate}

For the third-cycle thesis template, the \gls{PDF} should use \textbf{PDF/A-3u}, as shown in \Cref{lst:exampleDocumentMetadata}. This is important as we want to attach JSON, BibTeX, source code (as well as possibly other types of files). Under PDF/A-3 any type of file can be embedded as an associated file inside the PDF stream.
When initialized with \texttt{pdfstandard = a-3u}, the \LaTeX{} kernel's \gls{PDF} management layer adjusts its internal \gls{XMP} validation schema (\texttt{pdfaid:part = 3} and \texttt{pdfaid:conformance = U}) so that the embed operations pass long-term archival preflight checks without validation errors.

By migrating from external \gls{XMP} post-processing to native kernel-level metadata declarations (as shown in \Cref{lst:hypersetupMetadata}), the template ensures that generated \gls{PDF} files remain compliant with automated deposit tools and accessible to downstream indexing engines. And for schema fields that \texttt{\textbackslash hypersetup} does not natively cover (such as PRISM volume/issue and Dublin Core publisher tags), it uses the kernel’s internal \gls{XMP} hook directly (as was shown in the latter part of \Cref{lst:informationforPDFfile}). Using \texttt{\textbackslash DocumentMetadata} automatically satisfies PDF/A \gls{XMP} validation without manual \gls{XMP} injection.

\Needspace*{8\baselineskip}
\begin{lstlisting}[language={[LaTeX]TeX}, caption={Using \texttt{\textbackslash hypersetup} for some metadata}, label=lst:hypersetupMetadata]
\hypersetup{
  pdftitle    = {[en]{{\mytitle}}, [sv]{{\myalttitle}}},
  pdfauthor   = {\myauthor},
  pdfsubject  = {\mydegreeandsubject},
  pdfkeywords = { ... }
}
\end{lstlisting}

\section{To achieve PDF/A when including existing PDF files}
\label{sec:PDFAforExistingPDFs}

There are several alternatives to consider when you want to include non-PDF/A compliant \gls{PDF} files in a thesis:
\begin{enumerate}
    \item\label{RecompileAlternative} If you have the source files (and the relevant copyright ownership or permissions), you can recompile them such that they are PDF/A compliant.
    \begin{description}[style=nextline, labelwidth=\widthof{\textbf{Disadvantage}}, leftmargin=!]
    \item[Advantage] PDF/A compliance --- it is also a \enquote{new} document and hence has its own copyright.
    \item[Disadvantage] You may lose the layout of the publication.
    \item[Note] Many monographs have chapters that are based on a specific publication, rewritten as a chapter (with, of course, a citation to the original publication).
    \end{description}
    
    \item\label{AttachAlternative} If your kappa (or thesis) is PDF/A-3u compliant, \textbf{attach} the non-PDF/A compliant files
    \begin{description}[style=nextline, labelwidth=\widthof{\textbf{Disadvantage}}, leftmargin=!]
    \item[Advantage] PDF/A-3u compliance allows the attachment of other kinds of files without breaking the containing PDF file's PDF/A-3u compliance. As a result, the \enquote{included files} are fully present.
    
    \item[Disadvantage] The attached files must be viewed separately and may not maintain their appearance in the future (as they do not include all fonts used, among other external dependencies).
    \end{description}

    \item\label{TransformAlternative} Transform the non-compliant \glspl{PDF} into compliant \glspl{PDF}
    \begin{description}[style=nextline, labelwidth=\widthof{\textbf{Disadvantage}}, leftmargin=!]
    \item[Advantage] The documents can be included in-place with \texttt{\textbackslash includepdf}.
    
    \item[Disadvantage] Doing the transformation can be \textbf{very} difficult. See \Cref{sec:nonPDFAcompliantPublications}. \textbf{Note:} It took nearly a week of effort to transform all the files to successfully get the PDF/A-3u verification shown in \Cref{sec:verificationOfAll}.
    \end{description}
\end{enumerate}


\subsection{Dealing with non-PDF/A compliant publications}
\label{sec:nonPDFAcompliantPublications}

This section describes the effort to transform the example publication so the full thesis, including publications, meets the PDF/A-3u requirements.

\subsubsection{Dealing with Paper A from rfc1235.txt.pdf}
\label{sec:dealingWithPaperA}
The sample paper \fname{rfc1235.txt.pdf} uses Courier, but the file does \textbf{not} embed this Adobe \textit{proprietary} font. One can replace this font with the \texttt{NimbusMonoPS-Regular} font by using the command shown in \Cref{lst:cleanrfc1235}. While the replacement font is \textbf{not} visually identical, it is metrically matched:
\begin{itemize}
    \item \textbf{The Outlines (Glyph Shapes):} \texttt{NimbusMonoPS} was created as an open-source clone of Adobe Courier. While their character widths, line heights, word spacing, and overall proportions are meticulously matched (\ie metrics are identical), the actual glyph designs have subtle differences in stroke weight, serifs, and spacing. Under a microscope, you can tell they are different font families.

    \item \textbf{The Layout:} Because the metrics (widths and spacing) match, the text wrapping, line breaks, page lengths, and overall formatting of the included paper will not shift.
\end{itemize}

Will NimbusMono be acceptable for \gls{KTH} and archival standards? The short answer is \enquote{Yes}. Archival bodies (enforcing PDF/A rules) care primarily about \textit{self-containment} and \textit{long-term readability}:
\begin{itemize}
    \item Every character is permanently baked into the file as vector outlines. PDF/A-3u strictly forbids depending on device fonts or un-embedded Base-14 references precisely because a digital archive must remain viewable decades from now, even if the user's computer does not have Adobe Courier installed. By embedding NimbusMono, the rendering engine will always have the exact outlines it needs.

    \item ToUnicode maps are fully integrated so the text remains searchable and highlightable.

    \item The layout is preserved without breaking pagination.
\end{itemize}

However, this clearly comes at the cost of not being visually identical at the pixel level.

The file is cleaned as shown in \Cref{lst:cleanrfc1235}.
\begin{lstlisting}[language={bash}, caption={Using ghostscript to correct the rfc1235 PDF file},label=lst:cleanrfc1235]
gs -o rfc1235\_clean.pdf -sDEVICE=pdfwrite -dPDFSETTINGS=/prepress rfc1235.txt.pdf
\end{lstlisting}

This works because Ghostscript does not bundle the original, proprietary Adobe font binaries; instead, it relies on high-quality, \textit{metric-compatible open-source font equivalents} created by URW++\footnote{Now known as URW Type Foundry GmbH, owned by Monotype Imaging Holdings Inc.} to render and process these fonts.
\begin{itemize}
    \item Courier is mapped to NimbusMonoPS-Regular.

    \item Times-Roman is mapped to NimbusRoman.

    \item Helvetica is mapped to NimbusSans.
\end{itemize}

\subsubsection{Dealing with Paper\_B}
\label{sec:dealingWithPaperB}
The example paper in \fname{Paper\_B\_one\_page.pdf} is not PDF/A compliant.
The veraPDF\footnote{veraPDF is stylized in lowercase --- \url{https://verapdf.org/}} report for this file highlights the exact violations propagating into the thesis \gls{PDF}:
\begin{enumerate}
\item \textbf{123 \enquote{DeviceCMYK} Color Space Violations (Rule \enquote{6.2.3.3 Test 2}):}
The Hindawi publisher layout (the orange/brown header band, lines, and logos) was authored with uncalibrated CMYK colors (\enquote{0.12 0.72 1.0 0.05 k}). Because \enquote{Paper\_B\_one\_page.pdf} contains no embedded CMYK OutputIntent dictionary, veraPDF flags every single CMYK fill and stroke operator.

\item \textbf{21 \enquote{DeviceGray} Color Space Violations (Rule \enquote{6.2.3.3 Test 3}):}
Grayscale text and borders were authored in uncalibrated \enquote{/DeviceGray} without an OutputIntent profile.

\item \textbf{Missing \enquote{CIDSet} in Font Descriptor (Rule \enquote{6.3.5 Test 3}):}
The font \enquote{VHFPLH+MinionPro-Regular} used by the publisher lacks the mandatory \enquote{/CIDSet} stream mapping its subset glyphs.

\item \textbf{Illegal Link Annotation Properties (Rule \enquote{6.5.3 Test 2 \& 3}):}
The clickable DOI URL (\enquote{[http://dx.doi.org/10.1155/2014/528407](http://dx.doi.org/10.1155/2014/528407)}) contains an annotation dictionary (\enquote{29 0 obj}) lacking standard \enquote{/Print} flags and containing non-conforming color arrays.

\item \textbf{Non-Standard XMP Metadata Extensions (Rule \enquote{6.7.9 Test 2 \& 3}):}
Hindawi injected CrossMark, NISO-JAV, and PRISM 2.1 properties (\enquote{crossmark:MajorVersionDate}, \enquote{jav:journal\_article\_version}, \etc) without an \enquote{extensionSchemas} container.
\end{enumerate}

The entire multi-stage pipeline that transforms the \gls{PDF} file  \fname{Paper\_B\_one\_page.pdf} into a \qty{100}{\percent} compliant PDF/A-3u file consists of:
\begin{description}[style=nextline, labelwidth=\widthof{\textbf{Disadvantage}}, leftmargin=!]

\item [Ghostscript] \Cref{lst:cleanPaperB} cleanups and converts all CMYK color channels, vector spaces, and fills into the device-independent sRGB color space.
\begin{itemize}
    \item \texttt{-sColorConversionStrategy=sRGB} and \texttt{-sProcessColorModel=DeviceRGB} forces Ghostscript to map all embedded CMYK vector artwork, fills, and strokes into standard sRGB, eliminating any raw DeviceCMYK operators that trigger veraPDF rule 6.2.4.3.

    \item \texttt{-dOverrideICC=true} ensures that existing embedded profiles that might conflict or cause color-space mismatches are overridden by the target sRGB conversion strategy.
\end{itemize}


\item[Python Part 1] See \Cref{lst:cleanPaperBone}, which:
\begin{itemize}
    \item Injects a universal fallback byte-range (\texttt{<00> <ff> <fffd>}) into \texttt{CMap} streams to safely handle any unmapped glyph indices.

    \item Allocates a custom \texttt{/ToUnicode} stream and explicitly linked it to WinAnsi-encoded fonts (such as Minion-Black).

    \item Generates baseline \texttt{CIDSet} descriptor tables for embedded CID font subsets.
\end{itemize}

\item[Python Part 1] 2B performs a regex-based cleanup pass to surgically strip out conflicting or overly strict \texttt{/CIDSet} property references that tripped the validator's conditional checks.
\end{description}

\begin{lstlisting}[language={bash}, caption={Using ghostscript to correct the Paper\_B PDF file},label=lst:cleanPaperB]
gs -o Paper_B_fully_rgb.pdf \
   -sDEVICE=pdfwrite \
   -dPDFSETTINGS=/prepress \
   -dPDFA=3 \
   -sProcessColorModel=DeviceRGB \
   -sColorConversionStrategy=sRGB \
   -dOverrideICC=true \
   -dEmbedAllFonts=true \
   -dSubsetFonts=true \
   -dForceEncodeFonts=true \
   -dPreserveGlyphNames=false \
   Paper_B_one_page.pdf
\end{lstlisting}

\begin{lstlisting}[language={Python}, caption={Python to fix up paper B},label=lst:cleanPaperBone]
import fitz
import re

doc = fitz.open("Paper_B_fully_rgb.pdf")

# 1. Define a standard ToUnicode CMap stream for WinAnsi fonts
cmap_content = (
    b"/CIDInit /ProcSet findresource begin\n"
    b"12 dict begin\n"
    b"begincmap\n"
    b"/CMapType 2 def\n"
    b"/CMapName /Custom-WinAnsi-ToUnicode def\n"
    b"1 begincodespacerange\n"
    b"<00><ff>\n"
    b"endcodespacerange\n"
    b"1 beginbfrange\n"
    b"<00><ff><0000>\n"
    b"endbfrange\n"
    b"endcmap\n"
    b"CMapName currentdict /CMap defineresource pop\n"
    b"end end"
)

cmap_xref = doc.get_new_xref()
doc.update_object(cmap_xref, f"<</Length {len(cmap_content)}>>")
doc.update_stream(cmap_xref, cmap_content)

patched_cmaps = 0
cleaned_cids = 0

# 2. General-case processing across all objects
for xref in range(1, doc.xref_length()):
    try:
        # A. Dynamically handle any unmapped ranges in CMap streams
        stream_data = doc.xref_stream(xref)
        if stream_data and b"begincmap" in stream_data:
            cmap_text = stream_data.decode("latin1", errors="ignore")
            # If the CMap lacks a fallback range, inject a safe universal bfrange
            if "endcmap" in cmap_text and "<fffd>" not in cmap_text:
                fallback_range = "\n1 beginbfrange\n<00> <ff> <fffd>\nendbfrange\n"
                cmap_text = cmap_text.replace("endcmap", fallback_range + "endcmap")
                doc.update_stream(xref, cmap_text.encode("latin1"))
                patched_cmaps += 1

        # B. General cleanup of conflicting /CIDSet entries from font descriptors
        obj_text = doc.xref_object(xref, compressed=True)
        if obj_text and ("FontDescriptor" in obj_text or "CIDSet" in obj_text):
            new_obj = re.sub(r'/CIDSet\s+\d+\s+0\s+R', '', obj_text)
            if new_obj != obj_text:
                doc.update_object(xref, new_obj)
                cleaned_cids += 1
    except Exception:
        continue

# 3. Explicitly link the ToUnicode stream to any WinAnsi fonts lacking it
for page_num in range(len(doc)):
    for font in doc.get_page_fonts(page_num):
        font_xref = font[0]
        obj_text = doc.xref_object(font_xref, compressed=True)
        if "/ToUnicode" not in obj_text and obj_text.endswith(">>"):
            updated_obj = obj_text[:-2] + f"/ToUnicode {cmap_xref} 0 R>>"
            doc.update_object(font_xref, updated_obj)

doc.save("Paper_B_one_page_final.pdf", garbage=4, deflate=True)
doc.close()
print(f"General-case processing complete: Patched {patched_cmaps} CMaps, cleaned {cleaned_cids} CIDSets.")
\end{lstlisting}

Regarding the Python snippet 2B, one might ask: Is this a good idea, or just removing the symptom?

This is a classic tension in digital preservation: \textbf{reconciling rigid, older archival standards with modern font engineering}. Removing the \enquote{/CIDSet} entry is indeed \textbf{treating the symptom} rather than fixing the root cause at the font-generation level. However, in the context of PDF/A-3u compliance, it is a pragmatic and technically safe workaround.

The mismatch happens because:
\begin{description}[style=nextline, labelwidth=\widthof{\textbf{The Specification Anchor}}, leftmargin=!]
    \item [The Specification Anchor] PDF/A-3 (ISO 19005-3:2012) normatively inherits its rules from \gls{PDF} 1.7 (ISO 32000-1). Under \gls{PDF} 1.7 rules, a subsetted CID font \textbf{must} include a \enquote{/CIDSet} stream, \ie a binary bitmask indicating which character IDs are present in the subset.
    
    \item [Modern Tooling vs. Legacy Rules] When modern engines (\eg LuaLaTeX, Ghostscript, or modern subsetters) build a \gls{PDF}, they either omit \enquote{/CIDSet} or generate a bitmask that strict validators, such as veraPDF, find fault with (\eg a mismatch between the bitmask and the actual glyph usage tables inside the font program).
    
    \item [The PDF 2.0 Shift] The committee behind PDF 2.0 (ISO 32000-2) deprecated \enquote{/CIDSet} precisely because it was redundant, error-prone, and caused more archiving headaches than it solved. Modern \gls{PDF} processors can inspect the embedded font program (\enquote{FontFile2} or \enquote{FontFile3}) directly to see what glyphs exist.
\end{description}

Is removing it safe? Yes, it is safe for long-term archiving and rendering, for a few key reasons:
\begin{description}[style=nextline, labelwidth=\widthof{\textbf{The Source of Truth Remains}}, leftmargin=!]
    \item [The Source of Truth Remains] The actual font subset data (\enquote{FontFile2}/\enquote{FontFile3}) is untouched and fully embedded. Any compliant PDF renderer gets its glyph data straight from the font program, not from the \enquote{/CIDSet} bitmask.
    \item [Bypassing the Rule] The PDF/A rule for \enquote{CIDSet} is conditional: \textbf{If} a \enquote{CIDSet} stream is present, it must be exhaustively accurate. By stripping the key entirely, you bypass the conditional validation check while leaving the core font intact.
\end{description}
While fixing it upstream in the LaTeX or Ghostscript compilation chain would be the \enquote{pure} architectural fix, surgically removing a deprecated, redundant metadata entry to satisfy a legacy validator is a standard and effective technique in PDF remediation.

Useful tools when tracking down VerPDF issues were the program \texttt{pdffonts}, \texttt{gs}, the \texttt{fitz} Python library (part of \texttt{PyMuPDF}), and Google's Gemini.

To address this, the Python code has to scan all objects across the document, detect any dictionary containing a forbidden Transfer Function (\texttt{/TR} or \texttt{/TR2}), and purge it programmatically. See \Cref{lst:cleanPaperDone}.

\begin{lstlisting}[language={Python}, caption={Python to fix up paper D},label=lst:cleanPaperDone]
doc = fitz.open("Paper_D_fully_rgb.pdf")

# 1. Define a standard ToUnicode CMap stream for WinAnsi fonts
cmap_content = (
    b"/CIDInit /ProcSet findresource begin\n"
    b"12 dict begin\n"
    b"begincmap\n"
    b"/CMapType 2 def\n"
    b"/CMapName /Custom-WinAnsi-ToUnicode def\n"
    b"1 begincodespacerange\n"
    b"<00><ff>\n"
    b"endcodespacerange\n"
    b"1 beginbfrange\n"
    b"<00><ff><0000>\n"
    b"endbfrange\n"
    b"endcmap\n"
    b"CMapName currentdict /CMap defineresource pop\n"
    b"end end"
)

cmap_xref = doc.get_new_xref()
doc.update_object(cmap_xref, f"<</Length {len(cmap_content)}>>")
doc.update_stream(cmap_xref, cmap_content)

patched_cmaps = 0
cleaned_cids = 0
removed_tr = 0

# 2. General-purpose processing across all document objects
for xref in range(1, doc.xref_length()):
  try:
    # A. Dynamically handle unmapped ranges in CMap streams
    stream_data = doc.xref_stream(xref)
    if stream_data and b"begincmap" in stream_data:
      cmap_text = stream_data.decode("latin1", errors="ignore")
      if "endcmap" in cmap_text and "<fffd>" not in cmap_text:
        fallback_range = "\n1 beginbfrange\n<00> <ff> <fffd>\nendbfrange\n"
        cmap_text = cmap_text.replace("endcmap", fallback_range + "endcmap")
        doc.update_stream(xref, cmap_text.encode("latin1"))
        patched_cmaps += 1
    # B. Clean up object definitions (uncompressed and compressed parsing)
    obj_text = doc.xref_object(xref, compressed=False)
    if not obj_text or obj_text == "null":
      obj_text = doc.xref_object(xref, compressed=True)
    if obj_text:
      updated = False
      # Strip /CIDSet references from font descriptors
      if "FontDescriptor" in obj_text or "CIDSet" in obj_text:
        new_obj = re.sub(r'/CIDSet\s+\d+\s+0\s+R', '', obj_text)
        if new_obj != obj_text:
          obj_text = new_obj
          updated = True
          cleaned_cids += 1
      # General-purpose purge of forbidden /TR or /TR2 keys across any dictionary
      if "/TR" in obj_text or "/TR2" in obj_text:
        # Matches any /TR or /TR2 dictionary key definition and removes it entirely
        new_obj = re.sub(r'/\s*TR2?\b\s*(?:\[[^\]]*\]|/[A-Za-z0-9#+-]+|\d+\s+\d+\s+R|<[^>]*>|\([^)]*\)|<<[^>]*>>)?', '', obj_text)
        # Fallback safety: if inline regex missed a multi-line format, clean line by line
        if new_obj == obj_text:
          lines = obj_text.splitlines()
          filtered = [l for l in lines if not re.search(r'/\s*TR2?\b', l)]
          new_obj = "\n".join(filtered)
        if new_obj != obj_text:
          obj_text = new_obj
          updated = True
          removed_tr += 1
      if updated:
        doc.update_object(xref, obj_text)
  except Exception:
    continue

# 3. Explicitly link the ToUnicode stream to any WinAnsi fonts lacking it
for page_num in range(len(doc)):
  for font in doc.get_page_fonts(page_num):
    font_xref = font[0]
    obj_text = doc.xref_object(font_xref, compressed=True)
    if "/ToUnicode" not in obj_text and obj_text.endswith(">>"):
      updated_obj = obj_text[:-2] + f"/ToUnicode {cmap_xref} 0 R>>"
      doc.update_object(font_xref, updated_obj)

doc.save("Paper_D_clean.pdf", garbage=4, deflate=True)
doc.close()
print(f"General-purpose processing complete: Patched {patched_cmaps} CMaps, cleaned {cleaned_cids} CIDSets, purged {removed_tr} TR keys.")
\end{lstlisting}

By injecting the fallback range right before \texttt{endcmap}, we ensure that any character codes missing from the publisher's sparse tables safely map to \texttt{<fffd>}, while the publisher's explicit character mappings retain precedence during text extraction.

\Cref{lst:cleanPaperGeneral} shows a clean, generalized, object-agnostic Python script\footnote{Available in \fname{README\_notes/pdf\_a3u\_remediator.py}.} that you can use as the universal recipe for any non-compliant publication \gls{PDF} (\eg Paper B, Paper D, or future inclusions). The approach is to repair incomplete CMaps rather than skipping them. Instead of only attaching a fallback to fonts that completely lack a /ToUnicode map, we inspect every font's CMap stream. If an existing CMap stream does not contain a broad fallback range (\ie \texttt{<00> <ff> <fffd>}), we append it to the stream. This ensures that any 8-bit character code lacking an explicit mapping falls back safely to \texttt{<fffd>}\footnote{See \Cref{sec:sixteenBitFallback} for further information.}, satisfying VeraPDF without breaking valid character mappings.

\begin{lstlisting}[language={Python}, caption={Python to fix up publications},label=lst:cleanPaperGeneral]
import argparse
import fitz
import re

parser = argparse.ArgumentParser(description="Remediate a publication PDF for PDF/A-3u compliance.")
parser.add_argument("input", help="Path to input PDF")
parser.add_argument("output", help="Path to output remediated PDF")
args = parser.parse_args()

doc = fitz.open(args.input)
cleaned_cids = 0
cleaned_tr = 0
patched_cmaps = 0

# 1. Universal structural cleanup and CMap patching across all objects
for xref in range(1, doc.xref_length()):
  try:
    # A. Safely append a fallback range to CMap streams lacking '<fffd>'
    stream_data = doc.xref_stream(xref)
    if stream_data and b"begincmap" in stream_data:
      cmap_text = stream_data.decode("latin1", errors="ignore")
      if "endcmap" in cmap_text and "<fffd>" not in cmap_text:
        # Injecting a fallback bfrange right before endcmap handles unmapped glyphs safely
        fallback_range = "\n1 beginbfrange\n<00> <ff> <fffd>\nendbfrange\n"
        cmap_text = cmap_text.replace("endcmap", fallback_range + "endcmap")
        doc.update_stream(xref, cmap_text.encode("latin1"))
        patched_cmaps += 1
    # B. Fetch object text for dictionary cleanup
    obj_text = doc.xref_object(xref, compressed=False)
    if not obj_text or obj_text == "null":
      obj_text = doc.xref_object(xref, compressed=True)
    if obj_text:
      updated = False
      # Clean up conflicting /CIDSet references from font descriptors
      if "FontDescriptor" in obj_text or "CIDSet" in obj_text:
        new_obj = re.sub(r'/CIDSet\s+\d+\s+0\s+R', '', obj_text)
        if new_obj != obj_text:
          obj_text = new_obj
          updated = True
          cleaned_cids += 1
      # Purge forbidden /TR or /TR2 keys anywhere they appear in dictionaries
      if "/TR" in obj_text or "/TR2" in obj_text:
        new_obj = re.sub(r'/\s*TR2?\b\s*(?:\[[^\]]*\]|/[A-Za-z0-9#+-]+|\d+\s+\d+\s+R|<[^>]*>|\([^)]*\)|<<[^>]*>>)?', '', obj_text)
        if new_obj == obj_text:
          lines = obj_text.splitlines()
          filtered = [l for l in lines if not re.search(r'/\s*TR2?\b', l)]
          new_obj = "\n".join(filtered)
        if new_obj != obj_text:
          obj_text = new_obj
          updated = True
          cleaned_tr += 1
      if updated:
        doc.update_object(xref, obj_text)
  except Exception:
    continue

doc.save(args.output, garbage=4, deflate=True)
doc.close()
print(f"Universal processing complete: Patched {patched_cmaps} CMaps, cleaned {cleaned_cids} CIDSets, purged {cleaned_tr} TR keys.")
\end{lstlisting}

\subsection{Cautionary statement}
\label{sec:cautionaryStatement}

While this section addressed a number of different types of publications, it does \textbf{not} necessarily follow that these methods will work for \textit{all} publications from \textit{all} publishers.

\subsubsection{16-bit Fallback}
\label{sec:sixteenBitFallback}
As mentioned in \Cref{sec:dealingWithPaperD}, \enquote{If an existing CMap stream does not contain a broad fallback range (\ie the 8-bit single-byte range \ldots)}; future work should consider:
\begin{itemize}
    \item Single-byte hex ranges (\ie \texttt{<00> <ff>}) are tailored for 8-bit font encodings (such as WinAnsi, MacRoman, or Standard encoding), which are standard in Western journal papers, patents, \glspl{RFC}, and older glspl{PDF}.

    \item If a publication uses a 16-bit wide-character CID font (common in CJK documents or complex symbol sets), character codes use 4-hex-digit ranges (\ e.g. \texttt{<0000> <ffff>}); thus, a broadened fallback will be needed.
\end{itemize}

Note that in the Adobe CMap Syntax Standard, the \enquote{beginbfrange} operator expects the layout:
\begin{quotation}
$$\text{<start\_code>} \quad \text{<end\_code>} \quad \text{<target\_mapping>}$$
\end{quotation}

No dots, dashes, or separators other than whitespace are permitted between the starting hex code and the ending hex code.

Additionally, angle brackets \enquote{< >} enclose hexadecimal strings. For a 16-bit wide-character range, each value requires 4 hex digits (\eg \enquote{0000} through \enquote{FFFF}), resulting precisely in \enquote{<0000> <ffff>}.

Defining a fallback for 32-bit characters is likely similar, but, as with the 16-bit case, is left for future work.
